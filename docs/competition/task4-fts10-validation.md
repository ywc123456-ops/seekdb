# fts10 增量优化及验证

用户提供的最新官方记录为 fts9，19.962/50，mean improvement 为 0.19962276748907976。该成绩只适用于 fts9；本轮不把本地测量换算为官方分数，不承诺满分。

本轮在 fts9 上减少四类开销：二进制排序规则直接按字节比较；TOKENIZE 省略默认参数的 JSON 构造和序列化；非 IK 默认参数避免 JSON 解析；已存在的字典加载器使用共享读锁取得引用，首次创建仍由写锁保护并再次查询。自定义参数保留验证路径。参数对象复用时仅更新相应解析器字段，保留其他字段，与原行为一致。

验证使用原生 Linux Release 编译，构建及日志位于 E 盘对应的 Linux 文件系统。四个生产源文件均与编译快照逐字节核对（仅统一换行符）。完整 SQL 差分覆盖分词、全部五种内置解析器的默认参数、显式参数、Unicode、空值、分数、排序、预编译阈值、跨批次并集及大量查询词。原始完整输出保存在 E 盘 task4-fts10-final。

原生回归测试共 10 项，包括 4096 组二进制比较与原始排序处理器的精确比较、随机英文字符处理和默认参数在新建及复用对象中的等价性。并发检查使用 8 个客户端，每版 4800 次分词，与 fts9 完整结果一致。

完整基准保持 ROWS=20000、BATCH=500、ROUNDS=3000、QUERY_ROUNDS=200、SAMPLES=3、WARMUP=30、SKIP_LOAD=0。查询命中数必须为 8001、11000、7332、20。另进行 fts9/候选/候选/fts9 的交错热路径测试，每类查询 5 个样本，每样本 1000 轮。分词测量有改善，普通查询和 LIMIT 收益仍受波动影响，未证明显著且稳定的综合提分。

官方基准、评分、数据生成及构建入口未修改。原始报告保存在 task4-loader-lock-results、task4-final-hotpaths 和 task4-fts10-final。需要在官方环境提交 fts10 后确认新成绩；fts9 继续保留作为已获分版本。

最终编译版本完整基准：三项构建耗时为 5.246/4.344/2.438 秒，总计 12.052 秒；IK/BENG 分词为 0.1394/0.1077 毫秒；中文/英文/混合/LIMIT 查询为 0.6875/1.0041/0.8022/1.7628 毫秒。SQL 往返基准为 0.0913 毫秒，明显不同于用户官方环境的 0.0264 毫秒，因此这些数值不能与官方耗时直接相除。最终版本的 10 项测试、完整 SQL 精确输出比较和每版 4800 次并发调用均通过。
